# 运行入口与保存核验

## 调用启动

任何实际调用先按learning-loop.md创建并持久保存started记录，再读取本文件并进入剧情分析、提示词、生图或检查。不因GitHub未连接而等待，不等用户反馈才开始记录。记录实际读取的规则版本；无法确定版本时写unversioned，不伪造已读新版。

已安装技能可直接读取其正文及对应参考文件。用户指定《分镜与人物生成运行规则》、个人技能入口无法使用，或已知入口仍是旧缓存时，通过可用文件检索读取该文件的最新版本，再执行同样工作流。用准确标题定位，并保留文件身份；不能只凭搜索摘要执行，也不能把旧聊天记忆说成已读最新版。没有可访问备用文件时，用当前实际读取的技能规则完成不受影响任务，说明版本范围。

用户本轮要求优先；已实际读取的新版规则覆盖同范围旧规则。项目特定人物、台词和站立要求只在对应项目生效，不能转为所有任务的默认。

## 复盘写回

主动检查目标与实际结果，分别记录用户要求、可观察事实和待验证方法。有新规则时修改对应技能正文、模板和检查项；没有则记no_new_rule。

原个人Skill保存失败时，将新规则与变更依据写回同一份可读取的备用规则文件，并更新版本；个人Skill状态另记skill_update_pending。后续任务继续读实际保存的规则版本。临时目录或GitHub写入成功不能代替原个人Skill安装完成。

不得把重复肤质修正失败归类为成功。格式检查、图片视觉检查、保存检查分别记录，不声称模型权重已训练或所有聊天都在后台被记录。

## 保存结果分开核验

| 项目 | 成功依据 |
| --- | --- |
| 记录持久保存 | 文件保存服务明确返回成功，后续更新保留同一文件身份与版本 |
| 备用规则更新 | 同一规则文件替换成功，版本与变更依据明确 |
| 个人Skill安装更新 | 保存流程完成，后台最终目录仍存在，正文和参考文件包含本次关键修改 |
| GitHub同步 | 提交成功，远端分支和相关文件实际读取匹配 |

原个人Skill保存后，按skill-creator要求等候后台处理并核对最终文件；初次保存返回成功不足以证明完成。GitHub遇到冲突先读最新内容合并，不覆盖无关修改，不强制推送。没有GitHub连接时标记github_pending即可。

旧入口无法加载新版时，直接使用：“读取《分镜与人物生成运行规则》的最新版，按它完成任务，并从本次调用开始记录。”不能声称旧Skill已经自动恢复。
